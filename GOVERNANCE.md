# Governance

SNEPPX-Algo is a **BDFL (Benevolent Dictator For Life) + Maintainer Council** project.

---

## BDFL

**Ammar [SNEPPX]** — <algoSNEPPX@gmail.com>

The BDFL has absolute and final authority over:

- All technical decisions
- Repository access and commit rights
- Release authority and scheduling
- Security vulnerability response
- Feature decisions and prioritization
- Architecture changes
- Community conduct enforcement
- License and legal matters
- Governance amendments
- Core Maintainer appointments and removal

---

## Core Maintainers

Core Maintainers (Tier 5) are trusted contributors who steward the project alongside the BDFL.

### Powers

- Full commit access to all repositories
- Architectural decision-making
- Merge PRs from all tiers
- Manage releases and versioning
- Nominate new Maintainers and Core Maintainers
- Vote on governance changes (BDFL has veto)

### Appointment

1. Hold Tier 4 (Maintainer) for ≥ 1 year
2. Demonstrate leadership in 3+ major releases
3. Contribute to governance documents
4. Unanimous approval from existing Core Maintainers + BDFL

### Removal

A Core Maintainer may be removed by:
- BDFL decision (with explanation)
- Voluntary resignation
- Extended inactivity (≥ 12 months)

---

## Maintainers

Maintainers (Tier 4) ensure quality and consistency.

### Powers

- Merge PRs from Tier 1–3 (squash or rebase)
- Manage releases for assigned modules
- npm/PyPI publisher rights
- Set technical direction for owned modules

### Appointment

1. Hold Tier 3 (Senior) for ≥ 6 months
2. 100+ commits in the project
3. Lead one major feature end-to-end
4. Nominated by a Core Maintainer, approved by BDFL
5. Pass Architecture Review with BDFL

---

## Senior Contributors

Senior Contributors (Tier 3) provide code review and mentorship.

### Powers

- Approve PRs from Tier 1–2
- Request changes on PRs
- Own modules
- Participate in roadmap discussions

### Appointment

1. Hold Tier 2 for ≥ 90 days
2. 5+ merged PRs (≥ 2 in target module)
3. Write and get approved a Design Document
4. Review 10+ PRs (≥ 5 with substantive comments)
5. Pass Security Review for assigned module

---

## Contributors

Contributors (Tier 2) submit production-quality code.

### Powers

- Submit pull requests
- Assigned to issues

### Appointment

1. Hold Tier 1 for ≥ 14 days
2. 2 accepted issue reports
3. Submit a PR meeting all acceptance criteria
4. Reviewed and approved by Senior+

---

## Succession

If the BDFL becomes unable to serve, the Core Maintainers (or a successor appointed by the BDFL prior to incapacitation) assume governance. Succession requires unanimous agreement among Core Maintainers.

## Governance Model

- Maintainer council with BDFL oversight
- Voting on governance changes (BDFL veto)
- No term limits
- No appeals process — BDFL decisions are final

## Conflict Resolution

The BDFL decides. Final. No appeals.

## Amendments

Governance documents may be amended by the BDFL or by a majority vote of Core Maintainers (subject to BDFL veto).
